## Что это за проект

Личный тренажёр билетов ПДД Испании (двуязычный: испанский + русский).
Всего билетов: **88** (по стандарту DGT), в каждом билете — **30 вопросов**.
Пользователь готовится к экзамену — **качество перевода и точность правильных ответов критичны**.

## Ключевые файлы (структура проекта)

| Путь | Роль |
|------|------|
| `data/tickets.js` | **БАНК ПАМЯТИ.** Массив `window.TICKETS_DATA = [ ... ]` со всеми билетами. Здесь хранятся готовые данные |
| `images/` | Все скриншоты вопросов. Билеты ссылаются на них через `images/<имя>.png` |
| `index.html` | Веб-интерфейс. **ПРАВИТЬ НЕ НУЖНО** — он сам подхватывает новые билеты по `ticketId` через `TICKETS_DATA.find(t => t.ticketId === N)` |
| `N тест/` | Папка со скриншотами билета N (исходник). Папка с номером = билет с этим номером |
| `data/README.md` | Этот файл — инструкция-память |
| `build_ticket.py` | Универсальный сборщик билетов (см. ниже) |
| `t{N}data.py` | Данные билета N в готовом виде (вопросы es/ru + правильные ответы), читает его `build_ticket.py` |

## Принцип работы

- В `index.html` уже есть 88 кнопок билетов. Данные добавляются в `tickets.js` билет за билетом.
- **Папка «N тест» = билет №N.** Сейчас наполнены билеты 1–22. Остальные показывают заглушку/предупреждение.
- Пользователь присылает в чат JSON билета N и кладёт фото в папку `N тест/`.
- Задача агента: перевести вопрос и ответы на русский, собрать билет по формату ниже, вставить в `tickets.js`.

## Точный формат записи одного вопроса (обязателен)

```
{
  "id": "CP:тM" или "CP:t{N}_q{M}",
  "questionEs": "вопрос на испанском",
  "questionRu": "перевод вопроса на русский",
  "image": "images/<имя файла>.png",
  "options": {
    "A": { "es": "вариант на испанском", "ru": "перевод" },
    "B": { "es": "...", "ru": "..." },
    "C": { "es": "...", "ru": "..." }
  },
  "correct": "A" | "B" | "C"
}
```

- `id`: если в JSON пользователя есть официальный код (типа `CP:321482`) — берём его; если нет — используем `CP:t{N}_q{1..30}`.
- `questionEs`: поле `question` из JSON пользователя.
- `questionRu`: **перевод, который делает агент** (стиль — как в билетах 1–10, аккуратный экзаменационный).
- `image`: реальное имя файла из папки `N тест/` (НЕ из JSON, если расширения различаются — проверять фактические файлы!).
- `options.A/B/C.es`: поля `answers[].text` из JSON.
- `options.A/B/C.ru`: перевод ответов (агент).
- `correct`: буква ответа, у которой в JSON `"correct": true`.

### ⚠️ Правило про 2 ответа (важно!)

Если в JSON пользователя у вопроса **только 2 варианта** (`answers` содержит 2 элемента), а сборщик требует 3 — **НЕ выдумывать третий реалистичный вариант и НЕ подбирать его по смыслу**. Третий слот заполняется **пустой заглушкой-маркером**, ровно как сделано в билете 12, вопрос 19:

- `correct` остаётся на одном из первых двух слотов (том, где в JSON `correct: true`).
- В `options` третий слот: `"C": { "es": "3", "ru": "3" }` (текст-маркер «3», пустой по смыслу).
- Это сигнал пользователю: реальных ответов в вопросе только 2, а C — техническая заглушка формата, НЕ вариант.

Применено: билет 12, вопрос 19 (A — «Sí.», B — «No.» ✅, C — «3») и билет 21, вопрос 18 (A — «A la derecha.», B — «A la izquierda.» ✅, C — «3»).

## Как устроен `tickets.js` (важно для вставки)

Файл = `window.TICKETS_DATA = [` + билеты + `];`.
Каждый билет:

```
{
  "ticketId": N,
  "title": "Билет №N",
  "questions": [ ...30 вопросов по формату выше... ]
}
```

Отступы: 2 пробела на уровень (как в файле). Между элементами массива — запятая.
**Билеты ВСТАВЛЯЮТСЯ ВНУТРЬ массива, перед закрывающей `];`.** Если вставляешь вручную — после предыдущего билета нужна запятая, и новый блок ставится перед `];` (не после).

## Подводные камни (проверено на практике — НЕ повторяй ошибок)

1. **Запятые:** билет добавляется внутрь массива перед `];`. Нельзя добавлять после `];`. Между `}` прошлого билета и `{` нового — обязательная запятая.
2. **Внутри вопроса:** после `correct` запятая НЕ ставится (это последнее поле). Запятая ставится после закрывающей `}` вопроса, если вопрос не последний. Внутри `options` — запятая после `A` и `B`, после `C` не нужна.
3. **Имена файлов:** скриншоты надо скопировать из `N тест/` в `images/` (иначе битые ссылки). Расширение в папке может отличаться от JSON (например, в JSON `.jpg`, а реально `.png`) — брать фактические имена из папки.
4. **Кириллица в терминале:** heredoc `<< 'EOF'` с кириллицей ломается в shell. Создавай файлы данных через `editor`, а не через heredoc.
5. **id:** если кода нет — паттерн `CP:t{N}_q{M}` (как в билетах 5 и 6).
6. **Замыкающая запятая в `t{N}data.py`:** после закрывающей `]` списка `QUESTIONS` НЕ должно быть запятой. Запись `],` превращает список в кортеж `( [ ...30 вопросов... ], )` → `len(QUESTIONS) == 1`, и `build_ticket.py` падает на `assert len == 30`. После генерации всегда проверяй: `python3 -c "import tNdata; print(len(tNdata.QUESTIONS))"` → должно быть `30` (тип `list`). Именно из-за этой ошибки 06.10.2026 билет 10 «не собирался».

## Рекомендуемый (дешёвый) способ сборки — `build_ticket.py`

В корне есть **универсальный** сборщик `build_ticket.py`, который:
- читает номер билета из аргумента (`python3 build_ticket.py 6`),
- импортирует данные из `t{N}data.py` (список кортежей + список имён файлов),
- генерирует блок билета в точном формате и **вставляет его внутрь** `tickets.js` перед `];` (сам ставит запятые корректно),
- проверяет, что количество вопросов = 30.

**Чтобы добавить билет N:**
1. Получить JSON от пользователя + проверить папку `N тест/`.
2. Скопировать скриншоты: `cp "N тест"/*.png images/`.
3. Создать `t{N}data.py` (за основу взять `t6data.py`): в `QUESTIONS` — 30 кортежей `(question_es, question_ru, индекс_правильного(0-2), [(es,ru),(es,ru),(es,ru)])`, в `FILES` — 30 реальных имён файлов из папки (в порядке вопросов).
4. Запустить `python3 build_ticket.py N`.
5. Провалидировать: `python3 -c` парсинг `tickets.js` как JSON (извлечь массив между `[` и `];`), проверить 30 вопросов, существование всех `images/`, что `correct` совпадает с JSON пользователя.

## Чек-лист качества (перед сдачей билета)

- [ ] JSON-структура `tickets.js` валидна (парсится).
- [ ] 5→6→7... билетов, по 30 вопросов в новом.
- [ ] Каждая `image` ссылается на существующий файл в `images/`.
- [ ] `correct`-ответы совпадают с JSON пользователя.
- [ ] Перевод на русский — полный (у вопроса и всех 3 ответов) и аккуратный.
- [ ] Порядок вопросов 1..30 соответствует `question_number` из JSON.
